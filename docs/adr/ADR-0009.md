## Konteks
IDR tanpa desimal; hindari galat pembulatan.

## Keputusan
BIGINT di DB, bigint/util money di kode. Tanpa Float/Decimal.

## Alternatif dipertimbangkan
NUMERIC/float.

## Konsekuensi
Sederhana dan aman. Serialisasi JSON BigInt perlu ditangani eksplisit (string).
